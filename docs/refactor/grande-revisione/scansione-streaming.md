# Scansione C — streaming per prima, download, menu (22/11, sonnet)

- **Modello**: già pronto. `StorageMode {device, stream}` (settings_store.dart:34, D-596..D-607). Riga di libreria = kind 0, oppure kind 2 con saved=1 (`libraryRowSql`, track_kinds.dart:26-38). Brano online non salvato = id negativo in `OnlineEntries` (online_entries.dart:55). «Salva» = `TrackRepository.saveStream` (track_repository.dart:350) via `LibraryAdder.add/saveNow` (library_add_providers.dart:26-62), ma solo se `storageMode == stream`, altrimenti scarica. Download = `promoteStreamRow` (:179), stessa riga; «Libera spazio» = `demoteToStream` (:215). Mancano solo il default `stream` e un nome per lo stato «scaricato». Oggi un utente nuovo parte `device`, salvo poco spazio libero (onboarding_pages.dart:~255).
- **Cartelle**: le cartelle scansionate stanno nella tabella `folders` (onboarding `FoldersPage`, onboarding_pages.dart:147; default `<Music>`). La cartella dei download è `downloadLocation` (settings_store.dart:73; default `<Music>/FreeKmusic`, platform.dart:64). Le due sono collegate solo da `libraryFolderFor` (youtube_providers.dart:128). Su Android 11+ c'è `MediaPublisher`.
- **Download**: un solo ingresso, `DownloadsNotifier.add` (youtube_providers.dart:281). Brano in cache: `StreamPromoter.promote` tiene lo stesso id. Brano non in cache: scan → riga NUOVA → `mergeShadowRow`/`DuplicateRepository.merge` (id diverso; playlist, preferiti e ascolti spostati) + `replaceQueueId`. La UI se ne accorge invalidando `downloadIndexProvider`.
- **Import playlist**: `PlaylistImportService` (1251 righe): `_process` :689 → `_queueDownload` :979 → `_tagSaved` :964. Salvare o scaricare dipende dalla modalità GLOBALE (import_providers.dart:63-66). Non c'è un'opzione per singolo import (`ImportOptions.linkOnly` non salva). Le righe hanno già `enrichLater`, quindi import e download sono separabili di fatto. Proposta: `ImportOptions.downloadToo` nel dialogo `import_preview_dialog.dart`, più un'azione «Scarica» di massa (riusa `keep_offline`).
- **Album parziale**: `AlbumDetailScreen` (album_detail_screen.dart:61) mostra solo `watchAlbumTracks` (library_queries.dart:283). `OnlineAlbumScreen(browseId)` (online_album_screen.dart:39) esiste già, con salva per brano. Manca il browseId: `ytm_catalog.searchAlbums` :116 non viene mai chiamato da lì. Proposta: salvare il browseId in `saveStream` quando il brano arriva da una pagina album; altrimenti risolverlo con una ricerca.
- **Menu ⋮**: `showTrackActions` (track_actions.dart:409-439) cattura il `Track` una volta sola e ascolta solo `downloadIndexProvider` (:426-428). Non ascolta `savedStreamKeysProvider`, la riga in DB né `onlineEntries.bound`, quindi dopo «salva» o dopo un download con id nuovo resta vecchio. Proposta: un provider unico `trackStateProvider` (online / salvato / scaricato) osservato dal menu e dal player.
- **Rischi**: le righe stream sono escluse da condivisione LAN (share_providers.dart:92), export playlist (playlist_exporter.dart:17), Android Auto (media_browse_tree.dart:181,212), sync dei file (track_file_sync.dart:60). Flavor `lite`: deve restare `device`. Offline: un brano non scaricato non suona senza rete.
- **Incongruenze notate**:
  - track_actions.dart:264-290: una riga ombra non salvata mostra insieme «Aggiungi alla libreria» e «Scarica»; il secondo scarica senza `saved`.
  - Il download tiene l'id solo se il brano è in cache.
  - online_album_screen.dart:72: «Scarica album» in modalità stream salva soltanto.
- **Piano proposto**: 1 menu vivo → 2 ponte album → 3 import con «scarica anche» e scarica di massa → 4 default stream per i nuovi utenti (solo `kEnableYoutube`), online «Aggiungi alla libreria» → 5 cartella unica.
